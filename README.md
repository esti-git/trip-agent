# 🗺️ Trip Agent: סוכן לתכנון טיול יומי

אג'נט שמקבל עיר מוצא, תאריך, זמן נסיעה מקסימלי ואם רוצים גם סוג טיול מועדף, ומתכנן טיול יומי שמתאים למזג האוויר וחוזר לפני השקיעה.

## הבעיה ולמה בחרתי בה

כשמתכננים יציאה ליום חופש, צריך לבדוק כמה דברים שתלויים זה בזה: מה מזג האוויר, איזה סוג טיול מתאים לו, אילו מקומות קרובים מספיק, ואם יש מספיק זמן עד החשכה. ביום גשום מחפשים מקום מקורה, בשרב מים וצל, וביום נעים נוף ומסלול. בדרך כלל עושים את זה בכמה אתרים שונים, וקל לפספס משהו, למשל לצאת מאוחר מדי ולסיים מסלול בחושך.

בחרתי בבעיה הזאת כי היא יומיומית, וכי אי אפשר לפתור אותה בשאלה אחת. כל צעד תלוי בתוצאה של הצעד הקודם, ולכן היא מתאימה לאג'נט ולא לתוכנית שמבצעת רשימת פקודות קבועה.

**מה האג'נט עושה:** בודק את התחזית, מחליט בעצמו איזה סוג טיול מתאים (אם המשתמש ביקש סוג מסוים, הוא מכבד את הבקשה, אלא אם מזג האוויר לא מתאים לה, ואז מציע חלופה ומסביר למה), מציע מקומות ומאמת כל אחד מהם על המפה, בודק את זמן הנסיעה ובונה לוח זמנים שמסתיים לפני השקיעה. אם מקום לא נמצא, רחוק מדי או לא מספיק עד השקיעה, הוא לומד מהתוצאה ומנסה מקום אחר. אם אין אפשרות טובה, הוא עוצר ומסביר למה.

## איך האג'נט עובד

| מרכיב נדרש | איך הוא ממומש |
|---|---|
| **קבלת מטרה** | עיר מוצא, תאריך, זמן נסיעה מקסימלי וסוג טיול מועדף (לא חובה) הופכים להודעת מטרה (`prompts.build_goal`) |
| **קבלת החלטות** | ה-LLM בוחר בכל צעד איזה כלי להפעיל, לפי המטרה ולפי מה שגילה עד עכשיו. בקוד אין סדר צעדים קבוע ואין אף `if` על מזג האוויר. כשהסוג המבוקש לא מתאים למזג האוויר, הוא מכריע בעצמו בין הבקשה לבין התחזית |
| **שימוש בכלים** | 4 כלים: איתור מקום, תחזית, זמן נסיעה ולוח זמנים (פירוט בהמשך) |
| **בחינת התוצאה** | כל תוצאה, כולל שגיאות, חוזרת ל-LLM. מקום רחוק → מחפש קרוב יותר. לא מספיק עד השקיעה → יוצא מוקדם יותר או מקצר את הביקור. שירות לא ענה → מנסה שוב |
| **תנאי סיום** | ה-LLM עונה בלי לבקש כלי: תוכנית מאומתת, או הסבר למה אין. עצירה בכל מקרה אחרי 15 צעדים |

הלולאה עצמה ([agent.py](agent.py)): שולחים ל-LLM את השיחה ← אם ביקש כלים, מריצים אותם ומחזירים לו את התוצאות ← חוזרים, עד שהוא עונה בלי לבקש כלי.

לפני כל קריאה לכלי, האג'נט כותב משפט קצר (💭) שמסביר מה הוא בודק ולמה, כך שאפשר לעקוב אחרי שיקול הדעת שלו.

### הכלים

| כלי | מה הוא עושה | מקור |
|---|---|---|
| `geocode` | שם מקום → קואורדינטות. משמש לאימות שכל מקום שה-LLM מציע באמת קיים | OpenStreetMap (Nominatim) |
| `get_weather` | תחזית ליום: טמפרטורות, גשם, רוח, UV, זריחה ושקיעה | Open-Meteo |
| `travel_time` | מרחק וזמן נסיעה משוער, והאם הם בטווח שהמשתמש ביקש | חישוב בקוד |
| `plan_schedule` | לוח זמנים מלא, ובדיקה שעוזבים את המקום לפחות חצי שעה לפני השקיעה | חישוב בקוד |

### מה ה-LLM מחליט ומה הקוד מבטיח

**ה-LLM מחליט:** איזה סוג טיול מתאים למזג האוויר, האם לכבד את הסוג שהמשתמש ביקש או להציע חלופה, אילו מקומות להציע, באיזה סדר לבדוק, מתי לצאת וכמה זמן לבלות, מה לעשות כשמשהו נכשל, ומתי לעצור.

**הקוד מבטיח:** דברים שחייבים להיות נכונים תמיד לא נשארים לשיקול הדעת של ה-LLM:
- **הקלט של המשתמש נבדק לפני שהאג'נט מתחיל.** עיר המוצא מאותרת על המפה וחייבת להיות יישוב (עיר, כפר או שכונה), התאריך בטווח התחזית וזמן הנסיעה הגיוני. אם השם מתאים רק למקום אחר, למשל "מודיעין עלית" בלי י' מצא את "ישיבת מיר מודיעין עלית", המשתמש רואה מה נמצא ומתבקש לנסות כתיב אחר. בבדיקות ראיתי שכשעיר המוצא לא נמצאה, ה-LLM "החליט" שהיא ליד עיר אחרת והמשיך לתכנן משם. עיר המוצא היא עובדה שהמשתמש נותן, לא החלטה של האג'נט.
- **הכלים בודקים את הקלט שה-LLM שולח.** קואורדינטות מחוץ לישראל, תאריך או שעה לא תקינים, או שעת יציאה שכבר עברה (כשהטיול היום), מחזירים שגיאה מסבירה, וה-LLM מתקן את עצמו. שתי הבדיקות האחרונות נוספו אחרי שראיתי בריצות שמודל קטן שלח בטעות נקודה במצרים, ושהאג'נט הציע לצאת ב-09:00 כשהשעה כבר הייתה 10:30.
- **ההסברים שמוצגים למשתמש נקיים.** `gpt-4o-mini` העתיק לפעמים את הארגומנטים של הכלי כ-JSON לתוך ההסבר שלו, גם אחרי שההנחיות ביקשו שלא. הקוד מסנן שורות כאלה (`agent.clean_thought`), כך שהתוצאה לא תלויה בכך שהמודל יציית.

## התקנה והרצה

**דרישות:** Python 3.10 ומעלה, ומפתח API של OpenAI (או מפתח חינמי של Gemini, ראו בהמשך).

1. **להוריד את הפרויקט:**
   ```bash
   git clone https://github.com/esti-git/trip-agent.git
   cd trip-agent
   ```

2. **ליצור סביבה וירטואלית ולהתקין את התלויות:**
   ```bash
   python -m venv .venv
   .venv\Scripts\python -m pip install -r requirements.txt
   ```
   (ב-Mac או ב-Linux: `.venv/bin/python` במקום `.venv\Scripts\python`)

3. **להגדיר מפתח:** ליצור מפתח ב-[OpenAI](https://platform.openai.com/api-keys), להעתיק את `.env.example` לקובץ חדש בשם `.env` ולהדביק בו את המפתח:
   ```
   LLM_API_KEY=sk-...
   ```
   הקרדיט של ה-API נפרד ממנוי ChatGPT. ריצה של האג'נט עם `gpt-4o-mini` עולה פחות מסנט.

4. **להריץ, בממשק או בטרמינל:**

   **ממשק בדפדפן (מומלץ):** צעדי האג'נט מופיעים בזמן אמת, ובסוף מוצגים כרטיסי סיכום ותוכנית הטיול.
   ```bash
   .venv\Scripts\python -m streamlit run app.py
   ```
   הדפדפן נפתח בכתובת `http://localhost:8501`.

   **טרמינל:**
   ```bash
   .venv\Scripts\python main.py
   ```
   האג'נט ישאל מאיזו עיר יוצאים, באיזה תאריך (עד 15 יום קדימה), מה זמן הנסיעה המקסימלי ואיזה סוג טיול (Enter = ללא העדפה).

5. **להריץ את הבדיקות** (לא צריך אינטרנט או מפתח):
   ```bash
   .venv\Scripts\python -m pytest
   ```

### הגדרות (`.env`)

| משתנה | חובה | ברירת מחדל | הסבר |
|---|---|---|---|
| `LLM_API_KEY` | ✅ | | מפתח ה-API |
| `LLM_BASE_URL` | | OpenAI | כתובת השירות |
| `LLM_MODEL` | | `gpt-4o-mini` | המודל הראשי |
| `LLM_FALLBACK_MODELS` | | (אין) | מודלי גיבוי לפי הסדר, למקרה שהמודל הראשי עמוס |

**כדי לעבוד בחינם עם Gemini במקום OpenAI**, מספיק לשנות את `.env`, בלי לגעת בקוד (מפתח חינמי ב-[Google AI Studio](https://aistudio.google.com/apikey)):
```
LLM_API_KEY=המפתח_של_Gemini
LLM_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai/
LLM_MODEL=gemini-3.5-flash
LLM_FALLBACK_MODELS=gemini-flash-latest,gemini-flash-lite-latest
```
המכסה היומית החינמית של כל מודל ב-Gemini קטנה (בבדיקות שלי היא נגמרה אחרי כמה ריצות), ולכן כדאי להגדיר מודלי גיבוי.

## טיפול בשגיאות

- **כלים לא קורסים.** כל תקלה (שירות שלא ענה, מקום שלא נמצא, קלט לא תקין) חוזרת ל-LLM כ-`{"error": "..."}` עם הסבר, וה-LLM מחליט מה לעשות. גם בקשה לכלי שלא קיים או ארגומנטים שגויים מחזירים שגיאה מסודרת (`tools.run_tool`).
- **ה-LLM עמוס או חרג ממגבלת שימוש:** ניסיונות חוזרים, ואז מעבר למודל הגיבוי הבא. האג'נט זוכר איזה מודל עבד, ולא מנסה שוב מודלים שנכשלו.
- **מפתח חסר או שגוי, או שאין חיבור:** הודעה ברורה בעברית ויציאה מסודרת, בלי traceback.
- **קלט שגוי מהמשתמש:** הסבר בעברית ושאלה חוזרת. אפשר לבטל בכל רגע עם Ctrl+C.
- **הגבלת זמן לכל בקשת רשת**, והמתנה של שנייה בין פניות ל-Nominatim, כפי שהשירות דורש.

## החלטות והנחות

- **OpenAI עם `gpt-4o-mini`, כמו שההוראות ממליצות.** התחלתי עם Gemini כי הוא חינמי, אבל המכסה היומית החינמית נגמרה כבר בזמן הפיתוח, ומודלים עמוסים לא ענו. החיבור כתוב עם ספריית `openai` ומוגדר דרך `.env`, ולכן כל ספק שתואם ל-OpenAI (גם Gemini) עובד בלי לשנות קוד. מודלי הגיבוי (`LLM_FALLBACK_MODELS`) נולדו מאותה בעיה של עומס.
- **`geocode` מחפש גם מחוץ לקוד המדינה `il` ומעדיף מקום אמיתי על פני רחוב.** הרבה אתרי טיול (כפר עציון, קומראן, הרודיון) ממופים ב-OpenStreetMap תחת קוד מדינה אחר, ובלי זה החיפוש "כפר עציון" החזיר את רחוב כפר עציון בירושלים.
- **המקומות מגיעים מה-LLM ומאומתים מול המפה.** תכננתי לחפש אטרקציות במאגר של OpenStreetMap (Overpass API), אבל בבדיקות השירות לא החזיר תשובות. ה-LLM מכיר היטב את מקומות הטיול בישראל, ו-`geocode` מוודא שכל מקום שהוא מציע באמת קיים.
- **זמן הנסיעה הוא הערכה:** מרחק בקו אוויר × 1.3, במהירות ממוצעת של 60 קמ"ש. שירות ניווט חינמי לא היה אמין מספיק, וההערכה מספיקה כדי לבחור בין יעדים. ההנחות מוגדרות כקבועים בראש [tools/travel.py](tools/travel.py).
- **"חזרה לפני השקיעה"** = עוזבים את המקום לפחות 30 דקות לפני השקיעה, כדי לא לסיים מסלול בחושך.
- **ישראל בלבד**, ותחזית עד 15 יום קדימה (המגבלה של Open-Meteo).
- **`truststore`** משתמש בתעודות האבטחה של מערכת ההפעלה. בלעדיו Python לא מתחבר לאינטרנט מאחורי סינון כמו NetFree. במחשב רגיל הוא לא משנה כלום.
